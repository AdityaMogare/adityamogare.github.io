Intro

Students ask questions in a class Discord all week. Teaching assistants answer them one at a time, but nobody sees the pattern: which syllabus topics keep coming up, which never do, and which questions stay unresolved.

StudyAI passively captures those questions, maps each one to a syllabus topic with CockroachDB vector search, tracks whether it was resolved, and turns the class's collective blind spots into a TA plan.

Problem

TAs only find out which topics a class quietly struggled with when the exam results come in.

✎

Solution

Every question is embedded and linked to a syllabus topic; a weekly job finds untouched topics and open clusters and drafts a plan.

✦

Results

A Friday Discord report with coverage, open questions, and a TA plan, plus slash commands for students to drill weak topics.

Architecture

From a Discord message to a syllabus topic

A small gateway relay forwards new messages and reactions to API Gateway. The ingestion Lambda embeds the question with Bedrock Titan, stores it, and runs a vector nearest-neighbor query to link it to syllabus topics. Every action the agent takes is written to an agent_actions table.

Discord#questions, /ask → Gateway relay → API GatewayEd25519 verified → Ingestion LambdaTitan embedding → CockroachDB VECTORtopic link if L2 < 0.3

Syllabus topics are loaded ahead of time: a CLI extracts topics from the syllabus with Claude, embeds them, and writes them to the same table.

Resolution happens in Discord too: /resolved, a ✅ reaction, or a button updates the question's status and logs it, so coverage reflects what was actually answered, not just what was asked.

Acting on memory

The Friday report

An EventBridge cron fires every Friday and runs the gap-report Lambda. It reads topic coverage and recent questions, then posts a Discord embed to the exam-prep channel with untouched topics, open question clusters, and a recommended TA plan written by the model.

TAs can also pull it on demand with /gap-report or /memory. For students, /drill asks one question and waits for an answer, and /interview-ready lists topics they've never drilled or keep failing.

Key decision

Local first, cloud when ready

The same handlers run on a local FastAPI runtime with SQLite and no AWS account, or as Lambdas deployed with AWS SAM. That means the agent can run against a real Discord server before anything is deployed, and AWS is only needed once the data looks right.

Answers degrade gracefully: /ask tries OpenAI, then Bedrock, then a static course pack, with a configurable daily cap so a busy week can't run up the bill.

Reliability

Built to fail quietly, not loudly

  • Idempotent writes: questions are upserted on Discord message ID, so retries never double-count.
  • Verified requests: the interactions endpoint checks Discord's Ed25519 signature.
  • Least privilege: the Lambda role can only invoke the model.
  • Partial results: if the model call fails, the gap report still posts coverage.
  • Audit trail: every link, resolve, and report is queryable in agent_actions, so a TA can see why a topic was flagged.
